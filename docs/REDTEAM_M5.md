## §1. Удавшиеся атаки

### RT5-A1 — BLOCKER. Дефект в `Dcel::assemble`, срабатывающий только выше 16 px, проходит ВСЁ, что построил M5

`docs/REPRODUCIBILITY_M5.md` §5 сам предлагает эту атаку двумя пунктами: п.2 «правь `succ` так, чтобы поведение менялось только выше некоторого размера — размерная ось должна это увидеть» и п.3 «сделай `assemble` неверным так, чтобы он согласовывался сам с собой — инварианты построения обязаны это поймать». Обе защиты не сработали.

**Мишень.** `Parts::face_of_padded_px` — карта пиксель → грань, подпорка публичного `Dcel::face_of_pixel`. Это самое большое поле структуры: на 155 160 слотов обхода мутаций оно даёт подавляющее большинство.

**Никто его не читает.** `audit()` обращается к `boundaries`, `vertices`, `faces`, `site`, `half_edges`, `next`, `face_of`, `foreground_faces`, `holes`, `segment_count` — и НИ РАЗУ к `face_of_padded_px`. `is_the_assembly_of_its_own_labelling` сравнивает со свежей сборкой, то есть слеп к систематически неверному `assemble` (это сказано в его собственном доккомментарии). Во всём воркспейсе `face_of_pixel` читается ровно двумя утверждениями — `crates/vice-topology/src/dcel/mod.rs:639-640`, два выбранных руками пикселя одного диска 9×9.

**Правка (10 строк, `crates/vice-topology/src/dcel/mod.rs`, перед `Dcel { labelling, conn, … }`):**

```rust
let mut face_of_padded_px = face_of_padded_px;
if w >= 16 {
    let nf = faces.len() as u32;
    for v in face_of_padded_px.iter_mut() {
        *v = (*v + 1) % nf.max(1);
    }
}
```

Всё остальное — владельцы, петли, сайты, вершины, пути — остаётся верным. Порог 16 px ниже любого корпусного размера (32…512) и выше любой юнит-фикстуры крейта.

**Результат — измерено, не предположено:**

|---|---|---|
| весь набор тестов | `cargo test --locked --release --workspace` | **0 failed** во всех 30 бинарях |
| гейт §28 M5 | `gt-corpus dcel --out runs/m5/attack.json --scope full` | **EXIT 0, четыре `[MET]`**, все числа побитово те же |
| Tier A артефакт | SHA-256 `attack.json` vs `docs/gt/DCEL_M5.json` | `64939C1B…AB2A03A2` = `64939C1B…AB2A03A2` — **байт в байт** |
| единственный шаг M5 в CI | `gt-corpus dcel-check --report docs/gt/DCEL_M5.json` | `dcel report reproduced with every metric compared`, **EXIT 0** |
| исчерпывающая ось | `cargo test -p vice-topology --test dcel_props -- --ignored` | **2 passed, 0 failed** (в т.ч. 4×4, 131 072 расстановки) |
| нокауты | `cargo test -p vice-bench --test dcel_harness -- --ignored` | **4 passed, 0 failed** |

**Правило класса — и это, по-моему, ВОСЬМОЙ уровень, который просили найти.** Уровни, названные governor-ом (имена → типы → продукт типа → область проверки → судья → область доказательства судьи → плотность выборки), все про ВХОД. Восьмой — про ВЫХОД: **исчерпанность области входов и исчерпанность проверяемых полей значения — независимые свойства, и механизм, сделавший первое проверяемым компилятором, был принят за механизм, делающий проверяемым второе.** `Parts::perturbations` исчерпывающе деструктурирует `Parts`, поэтому поле без ВОЗМУЩЕНИЯ не компилируется — это настоящий судья. Но `audit()` — это семь пронумерованных блоков, написанных руками: литерал, перечисляющий свои предметы, F-0048 Q1 = ДА. Ничто не требует, чтобы у поля была ПРОВЕРКА. Перебрать все 65 536 разметок 4×4 не даёт ничего полю, которого не читает ни один предикат.

Число, которое это говорило, уже напечатано: `caught_by_audit / slots = 5648 / 155160 = 3.6 %`. Оно опубликовано как честная слабость аудита, а читается оно как **покрытие: 96.4 % слотов структуры не проверяются ничем настоящим** — потому что второе число, которое должно было их закрыть, тождество (RT5-A2).

### RT5-A2 — BLOCKER. `caught_by_neither == 0` — теорема, а не измерение; клауза 4 отличает полный аудит от аудита из одной проверки ровно одним битом

**Доказательство тождества.** В `measure_audit_resolving_power(d)` величина `d` всегда — результат `Dcel::assemble`, значит `d.parts() == assemble(d.labelling, d.conn).parts()`. Возмущение, не изменившее `parts`, отсеяно как `no_op`. Для остальных `parts != d.parts()`, а `broken` несёт ту же разметку и ту же конвенцию, поэтому

```
is_the_assembly_of_its_own_labelling(broken)
  = (assemble(broken.labelling, broken.conn).parts() == broken.parts())
  = (d.parts() == parts)
  = false     всегда
```

Значит `b == true` всегда, `caught_by_neither == 0` **не может быть иным**, а `caught_by_assembly_equality == slots − no_ops` тождественно. Автор это и утверждает в юнит-тесте — `assert_eq!(by_assembly, ps.len(), "assembly equality is total")` — но в гейт-строке `p.caught_by_neither == 0` стоит как КОНЪЮНКТ, а `report.rs` называет его «the property». Это ровно то, что запрещают M45-N5 / F-0035, записанные в шапке того же файла: конъюнкт, который не может быть ложным, измеряет размер входа.

**Что тогда реально требует клауза 4 от аудита?** Только `p.caught_by_audit > 0`. Один пойманный слот.

**Правка.** `audit()` сведён к диапазонным охранам (чтобы прибор сообщал, а не падал) плюс ОДНА содержательная проверка — метка внешней грани. Удалено: `successor_is_a_permutation`, проверка единичного шага решётки, проверка вершинных концов, «каждая граница использована дважды», согласие `next` с владельцами, тождество Эйлера `V − B + L = 2C`, сверка с независимой сигнатурой. То есть **весь седьмой инвариант §12** — тот единственный, который M5 объявляет вычислением (STATUS T2, traceability M5-7).

**Результат:**

```text
$ gt-corpus dcel --out runs/m5/attack2.json --scope full
  audit resolving power: 28 arrangements of 474 arms, 155160 slots, audit 268, assembly 155160, neither 0
  [MET] × 4        EXIT 0

$ cargo test --locked --release --workspace
  0 failed  (все 30 бинарей)
```

`caught_by_audit` падает 5648 → 268, `caught_by_neither` остаётся 0 ровно как предсказано, и **ни гейт, ни один из 530 тестов, ни обход мутаций на 155 160 слотах не отличают полный аудит от аудита, проверяющего одну метку.** Порога на `caught_by_audit` в замороженной секции `[dcel]` нет: `gate_min_resolving_power_probes = 10` считает ПРОБЫ, а не пойманное.

**Правило класса.** Прибор, измеряющий разрешающую способность судьи, обязан сам быть проверен на то, что его вердикт зависит от судьи. Здесь из трёх опубликованных чисел два — арифметика (`neither`, `assembly`), и только третье (`audit`) несёт информацию; но конъюнкт стоит на первом, а третье входит порогом `> 0`. Конъюнкция «тождество ∧ (x > 0)» имеет разрешающую способность в один бит, а публикуется как измерение на 155 160 слотах.

СТАЛО: stored_map   == g(boundaries)                 — пересчёт не читает возмущённое поле → срабатывает всегда
