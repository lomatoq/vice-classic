# REPRODUCIBILITY_M3_5 — воспроизведение артефактов M3.5

Дополняет `docs/REPRODUCIBILITY_M3.md`, не заменяет его: корпус, scorecard и
burn policy воспроизводятся ровно теми же командами, что и в M3. Здесь —
только то, что добавил M3.5: факториальный oracle harness и его артефакт
`docs/gt/ORACLE_M3_5.json`.

## Окружение

То же, что в `REPRODUCIBILITY_M3.md` §«Окружение»: `rust-toolchain.toml`
пиннит 1.96.0, `Cargo.lock` закоммичен, короткий путь checkout-а (F-0004).

## Команды

```bash
# Прогнать harness и записать артефакт (full scope: 63 сцены, 4 ячейки,
# 2 backend-а, 504 arms). На машине автора — около 1 секунды: измерение
# идёт на 32 px и не трогает суперсэмплер.
cargo run --release --bin gt-corpus -- oracle \
  --out docs/gt/ORACLE_M3_5.json --scope full

# Сверить ЗАКОММИЧЕННЫЙ артефакт: пересобирает в его собственном scope и
# сравнивает всё.
cargo run --release --bin gt-corpus -- oracle-check \
  --report docs/gt/ORACLE_M3_5.json
```

Ожидаемый вывод второй команды на платформе записи:

```text
oracle report reproduced with every metric compared
```

Exit-коды: `0` — сошлось; `1` — не сошлось (находка); `2` — типизированный
отказ (не та платформа, нечитаемый файл).

## Что при сверке может законно отличаться

**Платформа.** Метрики oracle — это float-ы, полученные через libm
(`sin`/`cos` в геометрии корпуса, `powf` в цвете), поэтому артефакт —
**Tier A** по §5.5, ровно как render-дайджесты корпуса (F-0020, ADR-0008 §8).
Артефакт НЕСЁТ свою платформу, и `oracle-check` на другой платформе
**отказывает** с exit 2, называя обе:

```bash
# Кросс-платформенная сверка возможна только по явному флагу и только для
# платформенно-НЕЗАВИСИМОЙ проекции; вывод сам говорит, что метрики не
# сравнивались.
cargo run --release --bin gt-corpus -- oracle-check \
  --report docs/gt/ORACLE_M3_5.json --structural
```

Проекция сохраняет: состав, идентификаторы arms, `key_fingerprint`,
статус inverse crime, все типизированные отказы, gate-таблицу и
`config_hash`. Она НЕ сохраняет ни одной измеренной величины — то есть она
не является инструментом §5.5 Tier B и не выдаётся за него (см.
`docs/STATUS_M3_5.md` §5, ограничение 1).

**На ОДНОЙ платформе не может отличаться ничего.** Расхождение метрики при
совпадающей платформе — находка, а не шум: harness детерминирован, что
проверяется тестом `oracle::tests::the_run_is_deterministic`.

## Что именно сверяется

| Величина | Где | Как проверяется |
|---|---|---|
| `config_hash` | шапка артефакта | компонент compatibility key (§27.6); зависит от scope, backend-ов, ячеек и списка метрик |
| `fixture_set_hash` | шапка артефакта | sha256 отсортированных scene digest-ов: привязывает прогон к конкретному корпусу |
| 504 arm-а G30 | `ceiling_arms` | пересборка и побайтовое сравнение JSON |
| 8 агрегатов | `ceiling` | статус inverse crime пересчитывается как fold своих же arms |
| 6 факториалов × 3 эффекта | `factorial` | каждый — либо commensurable contrast, либо типизированный отказ |
| gate table §28 M3.5 | вывод команды | `oracle` возвращает 1, если любая клауза не выполнена |

## CI

Два job-а в `.github/workflows/ci.yml`, и они проверяют РАЗНОЕ:

| job | раннер | что сверяет |
|---|---|---|
| `gt-corpus` | ubuntu | прогоняет harness целиком (гейт-таблица исполняется, ненулевой exit при провале любой клаузы) и `oracle-check --structural` на закоммиченном артефакте — то есть СОСТАВ, идентичности arms, статусы inverse crime и отказы |
| `tier-a-digests` | windows | `oracle-check` БЕЗ флага и `verify` манифеста БЕЗ флага — то есть **сами цифры**: 504 метрики и 1086 render-дайджестов |

Второй job — закрытие условия A7.2 из `REVIEW_M3`: до него цифры
закоммиченных артефактов не сверял в CI никто, и они держались на ручном
прогоне на платформе записи. Windows-раннер несёт ту же пару `(os, arch)`,
что записана в артефактах, поэтому платформенная проверка проходит и
сравнение идёт полное.

**Что означал бы провал `tier-a-digests` при зелёном структурном шаге:** это
та же сигнатура, что нашла F-0020, и она означала бы, что `(os, arch)` —
слишком грубое имя для условия Tier A (например, различаются версии UCRT).
Это находка о контракте артефакта, а не повод перезапустить job.
