# ADR-0013 — Типизированный числовой домен рендера (корень F-M2-R1/R2/R3)

Дата: 2026-07-26. Статус: accepted (M2, после REDTEAM_M2 FAIL).

## Контекст

Red-team pass §34 нашёл три MAJOR-дефекта и сформулировал их общий корень:
**«числовой домен системы нигде не выражен типом»**. Проявления:

1. `f64 → u32` конверсия числа кусков без явного домена → panic на
   валидной сцене, debug ≠ release (F-0007, F-M2-R1);
2. замороженный допуск 1e-9 обоснован «для canvas до 2^12», при том что
   единственный enforced-лимит (`MAX_COVERAGE_ELEMENTS`) допускал ширину
   до 2^26, а валидация — ЛЮБУЮ конечную координату; между обоснованием и
   допущенным лежало пустое место, и внутри него неверное значение
   возвращалось МОЛЧА (F-0008, F-M2-R2);
3. стоимость обхода колонок не была ограничена ни canvas-ом, ни доменом
   координат (F-0009, F-M2-R3).

Точечные заплатки по каждому проявлению оставили бы корень на месте.

## Решение

**Домен — это тип.** `vice_render::domain::NumericDomain` описывает
область координатного пространства и размеров canvas, на которой
доказаны и enforced числовые границы рендера:

```rust
pub struct NumericDomain {
    pub max_abs_coord_px: f64,   // 2^16 = 65536
    pub max_canvas_dim_px: u32,  // 2^14 = 16384
}
```

Три следствия, каждое — отдельная точка контракта:

1. **Допуск выводится ИЗ домена, а не соседствует с ним.**
   `PartitionTolerances::for_domain(&domain)` = `max(FROZEN_FLOOR,
   domain.coverage_error_bound_px())`. Замороженный пол 1e-9 остаётся
   значением для дефолтного домена; каллер, сознательно расширивший
   домен, получает ЯВНО расширенный допуск, а не молча
   инвалидированный старый.
2. **Выход за домен — типизированный отказ.**
   `RenderError::OutsideNumericDomain { what, value, limit }` на полном
   рендере, на ROI-пути и, следовательно, на seal-пути. Раньше сцена с
   координатой 1e12 рендерилась и возвращала числа, чья ошибка не
   ограничивалась ничем, что стражи партиции способны увидеть.
3. **Границы домена — измеряемые, а не декларативные.** In-tree
   translation oracle (`tests/coverage_domain_gate.rs`, инструмент red
   team, перенесённый в репозиторий) меряет фактическую ошибку по всему
   домену и сверяет её с `coverage_error_bound_px()`.

### Выбор чисел

| Параметр | Значение | Обоснование |
|---|---|---|
| `max_canvas_dim_px` | `2^14` = 16384 | Растровый класс ядра (логотипы, иконки, клипарт) лежит далеко ниже; сохраняет совместимость с существующим `CanvasTooLarge`-порогом |
| `max_abs_coord_px` | `2^16` = 65536 (4× canvas) | Геометрия ЗАКОННО выходит за canvas (ADR-0009: control-polygon overshoot; M7 двигает ручки через край), поэтому координатная граница обязана быть строго щедрее canvas-ной |
| `coverage_error_bound_px` | `16·eps·M` = 2.33e-10 | Измеренный до-фикс закон red team ≈ 1.1e-16·M; `16·eps` ≈ 3.6e-15 на единицу — ~32× запас по наклону. Под замороженным 1e-9 с запасом 4.3×; над измеренным худшим случаем (2.4e-12 при 2^16) с запасом ~95× |

### Почему допуск нельзя было просто сделать тоньше

Ошибка после column-local trapezoid (F-0008) — это уже НЕ ошибка
интегрирования, а предел ПРЕДСТАВЛЕНИЯ: позиция ребра, интерполированная
при магнитуде `M`, известна только с точностью `ulp(M)`. Никакая схема
интегрирования не восстанавливает точность, которой нет во входе. Поэтому
единственный честный ответ — объявить область, где `ulp(M)` пренебрежима
против допуска, и отказывать за её пределами.

Измеренная слоистая граница (in-tree oracle, наклонная недиадическая
фигура):

| offset | до фикса (red team) | после фикса | статус |
|---|---|---|---|
| 2^12 | 7.04e-13 | 2.79e-13 | в домене |
| 2^13 | 1.271e-12 | 5.50e-13 | в домене, под 1e-12 |
| 2^14 | 2.505e-12 | 1.51e-12 | в домене |
| 2^16 | 4.542e-12 | 2.43e-12 | граница домена |
| 2^24 | 1.732e-9 | 1.19e-9 | ВНЕ домена → typed reject |

Отсюда честная формулировка заявления (заменяет плоское «≤1e-12»):
по всему домену — `≤ coverage_error_bound_px()` (2.3e-10); в
мало-координатном режиме (≤ 2^13, покрывающем любой canvas этого ядра) —
`≤ 1e-12`.

## Последствия

- Сцены с астрономическими координатами (остров на 1e12), которые раньше
  рендерились «правильно, но без гарантий», теперь получают typed
  `OutsideNumericDomain`. Это сознательное изменение поведения в сторону
  честности; оно зафиксировано тестом и в STATUS_M2 «известные
  ограничения».
- Второй, независимый механизм честности сохраняется и не подменяется
  доменом: при больших координатах `verify_embedding` отказывается
  сертифицировать ориентацию, потому что shoelace-неопределённость
  превышает площадь loop-а. Расширение домена покупает документированный
  допуск, но НЕ приостанавливает сертификат.
- `MAX_COVERAGE_ELEMENTS` остаётся: он про АЛЛОКАЦИЮ, домен — про
  ТОЧНОСТЬ, а стоимость по времени ограничена отдельно (ADR-0009 после
  правки F-0009). Три разных ресурса — три разных явных лимита.
