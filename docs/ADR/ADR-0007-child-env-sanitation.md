# ADR-0007 — Санация окружения дочерних процессов и config-limits для verify-corpus

Дата: 2026-07-26. Статус: accepted (M1). Addendum к ADR-0002 (runner design);
закрывает REVIEW_M0 условие 5 (замечания N6 и N4).

## Контекст

REVIEW_M0 N6: `exec.rs` спавнил детей с полностью унаследованным ambient
окружением — сторонняя переменная (RUSTFLAGS, CARGO_TARGET_DIR,
PYTHONHASHSEED, …) могла изменить донорскую сборку/артефакты, не оставив
следа в отчёте. N4: `verify-corpus` игнорировал `[limits]` проекта и всегда
использовал встроенные defaults.

## Решение N6: фиксированная политика child-env (консервативный дизайн)

1. **Точка применения — одна:** `exec::run_with_timeout` (все build/run
   команды baseline-ов и selftest-adapter). Политика применяется каждому
   ребёнку без исключений.
2. **Удаляются** (фиксированный список `CHILD_ENV_REMOVE`):
   `RUSTFLAGS`, `RUSTDOCFLAGS`, `RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER`,
   `RUSTC_BOOTSTRAP`, `CARGO_ENCODED_RUSTFLAGS`, `CARGO_BUILD_RUSTFLAGS`,
   `CARGO_BUILD_RUSTDOCFLAGS`, `CARGO_INCREMENTAL`, `CARGO_TARGET_DIR`,
   `CARGO_BUILD_TARGET_DIR` — ровно те переменные, которые молча меняют
   результат донорской сборки или уводят её артефакты в другое место.
3. **Пиннится:** `PYTHONHASHSEED=0` для python-доноров (детерминизм
   set/dict-итерации). Безопасность относительно записанных M0 baseline-ов:
   в M0 повторы шли с РАЗНЫМИ случайными seed-ами процессов и дали
   побайтово одинаковые артефакты — значит выходы доноров от seed не
   зависят, и пиннинг не может изменить записанные хеши.
4. **НЕ делаем `env_clear`:** полная очистка сломала бы спавн (PATH,
   CARGO_HOME, TEMP, системные переменные Windows). Консервативный выбор —
   вычищать известный influence-вектор, а не гадать полный allowlist.
   Тест фиксирует, что PATH выживает.
5. **Политика — константа в коде,** не конфиг и не env: она не может стать
   скрытой ручкой поведения (§32 п.4). Чтение ПРИСУТСТВИЯ переменных для
   записи в манифест — это recording, не behaviour control.
6. **Запись в env.json:** новый блок `command_env` — `policy`
   (`vice-classic/child-env/v1`), `removed`, `set`,
   `ambient_overrides_present` (ИМЕНА переменных из списков, реально
   присутствовавших в ambient; значения намеренно не пишутся — после
   санации они не влияют на детей, а в значениях могут быть пути/секреты).
   Блок входит в `environment_sha256`.

### Совместимость с записанными M0-артефактами

`docs/baselines/M0/**` НЕ переписываются. Схема env.json расширена начиная
с C009: побайтовое сравнение env.json с записанным M0-артефактом имеет
смысл только на M0-коммитах (C002–C005); это отражено в
REPRODUCIBILITY_M0.md. Artifact-хеши доноров политика не меняет: на
записывающей машине ни одна из удаляемых переменных не была установлена
(пустой `ambient_overrides_present` это фиксирует в каждом новом прогоне).

## Решение N4: `verify-corpus --config`

`verify-corpus` принимает опциональный `--config`; при наличии — limits
берутся из `[limits]` конфига (после полной валидации схемы конфига;
непарсабельный конфиг = exit 2, никакого тихого отката на defaults). Без
флага поведение прежнее (встроенные defaults) — документированные команды
M0 продолжают работать без изменений.

## Верификация

- `tests/child_env.rs` (отдельный процесс: тест мутирует своё окружение):
  дети не видят RUSTFLAGS/CARGO_TARGET_DIR/RUSTC_WRAPPER; PYTHONHASHSEED
  переопределён на 0 поверх ambient 999; PATH выживает; env-манифест
  содержит политику и ambient-presence, значения не утекают.
- `tests/cli.rs::verify_corpus_takes_limits_from_config`: без конфига —
  exit 0; с абсурдно тесным `[limits]` — exit 1 (limits доказуемо из
  конфига); битый конфиг — exit 2.
- Существующие тесты vice-bench остаются зелёными; записанные
  M0-артефакты не тронуты.
