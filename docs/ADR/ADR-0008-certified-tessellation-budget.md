# ADR-0008 — Certified curve tessellation budget (vice-geom::flatten)

Дата: 2026-07-26. Статус: accepted (M2).

## Контекст

Spec v1.3 §16.1: «exact» renderer означает exact area coverage для
ФИКСИРОВАННОЙ polyline tessellation; шаг Bézier→polyline обязан нести
отдельный **certified** chord-error budget, а §5.4 требует, чтобы bounds
включали tessellation error и чтобы tolerances были типизированы по units.
«Certified» здесь значит: возвращаемое число — доказуемая верхняя граница,
а не эвристика «на глаз». Место в архитектуре: кривые принадлежат
vice-geom (§4: «Vec2, robust predicates, curves, intersections»);
vice-render только сопоставляет `vice_ir::Segment` с этими функциями.

## Решения

1. **Типизированный tolerance:** `ChordTolerancePx` (finite, `> 0` по
   построению). Единица — пиксели, назначение — max chord deviation.

2. **Béziers: chord interpolation bound.** Для C²-кривой `B` на интервале
   длины `h` линейный интерполянт `L` через концы даёт
   `max‖B − L‖ ≤ h²/8 · max‖B''‖` (классическое следствие теоремы Ролля:
   для φ(t) = B(t) − L(t), φ = 0 на концах; для каждой компоненты и каждой
   точки t* существует ξ с φ(t*) = φ''(ξ)·(t*−a)(t*−b)/2, а
   max|(t*−a)(t*−b)| = h²/4; итого h²/8·max|φ''| покомпонентно, и
   консервативно по норме). Так как `L(t)` — точка НА хорде, эта величина
   ограничивает расстояние и от кривой до polyline, и от хорды до кривой
   (симметричный Hausdorff-баунд).
   - Quad: `B'' = 2(p0 − 2c + p1)` — константа; при разбиении на `n`
     равных кусков bound = `|p0 − 2c + p1| / (4n²)`.
   - Cubic: `B''(t) = 6[(1−t)a + t b]`, `a = p0−2c1+c2`, `b = c1−2c2+p1`;
     `max‖B''‖ ≤ 6·max(|a|,|b|)`; bound = `(3/4)·max(|a|,|b|)/n²`.
   `n` выбирается из bound ≤ tol (плюс 1 на округление sqrt/деления), а
   сертифицированное значение ПЕРЕВЫЧИСЛЯЕТСЯ из фактического `n` — мы
   никогда не записываем запрошенный tol как достигнутый.

3. **Circular arc: сагитта.** Кусок дуги угла `φ` отклоняется от хорды
   ровно на `r(1 − cos(φ/2))`; `φ_max = 2·acos(1 − tol/r)`,
   `n = ceil(|Δθ|/φ_max)`. Endpoint→center конверсия выведена
   геометрически (перпендикуляр из середины хорды,
   `h = sqrt(r² − (chord/2)²)`; сторона центра: `+rot90_ccw(chord)` ⟺
   `ccw != large_arc`; sweep нормализуется в `(0, 2π)` для ccw и
   `(−2π, 0)` для cw). Покрыто тестами всех четырёх комбинаций флагов и
   полукруга `2r = chord`.

4. **Elliptic arc: линейное отображение.** Плоскость отображается
   `M⁻¹ = diag(1/rx,1/ry)·R(−φ)` в unit-circle-домен (det > 0 — sweep
   сохраняется), решается круговой случай, вершины отображаются назад
   `M = R(φ)·diag(rx,ry)`. Линейное отображение переводит отрезки в
   отрезки, поэтому `dev_ellipse ≤ ‖M‖·dev_circle`, `‖M‖ = max(rx,ry)`;
   бюджет достигается запросом `tol/max(rx,ry)` в круговом домене.

5. **Floating-point честность.** Внутренние вершины ВЫЧИСЛЯЮТСЯ в f64,
   поэтому к аналитическому bound добавляется guard
   `64·eps·max(|coord|, 1)` (консервативно против ошибок оценки полинома /
   sin/cos/центра). Концевые точки НЕ вычисляются: первый/последний
   элементы polyline — это битово те же shared chain points из графа,
   поэтому общая граница, tessellated один раз, не может дать crack между
   соседними faces.

6. **Budget honesty при cap.** Число кусков на кривую ограничено
   `MAX_SUBDIVISIONS = 2^14` (§29: no uncontrolled growth). Если cap
   сработал, возвращённый `max_deviation_px` — сертифицированный bound ПРИ
   cap (больше запрошенного); потребитель (vice-render) обязан сверить его
   с запросом и вернуть typed error, а не молча продолжить.

7. **Площадной бюджет.** Каждый кусок лежит в замкнутой δ-окрестности
   своей хорды, поэтому площадь между кривой и polyline ≤
   `Σ (2δ·|chord| + 4δ²)` (4 > π — консервативно). Экспортируется как
   `FlattenedCurve::area_error_bound_px2` и используется в embedding-
   сертификации ориентации loops (ADR-0010).

8. **Детерминизм.** Разбиение равномерно по параметру, число кусков —
   детерминированная функция входа; никаких adaptive-ветвлений по
   f64-сравнениям с промежуточными состояниями. Один и тот же вход даёт
   один и тот же polyline на одной платформе (Tier A). Кросс-платформенно
   Bézier-flattening использует только +,−,×,÷,sqrt,ceil (IEEE, correctly
   rounded) — воспроизводим и между платформами; дуги используют
   sin/cos/atan2/acos из libm — байтовая кросс-платформенность НЕ
   обещается (Tier A only), и замороженные digest-артефакты рендера не
   должны содержать дуг.

## Верификация

`vice-geom/src/flatten.rs` unit-тесты: измеренное расстояние dense-сэмплов
кривой до polyline ≤ certified bound (независимая брутфорс-метрика
точка-отрезок); битовая точность концов; все комбинации arc-флагов;
представимость полукруга; typed reject нерепрезентабельных дуг;
монотонность refinement; поведение budget honesty дополнительно
проверяется в vice-render (TessellationBudgetExceeded).
