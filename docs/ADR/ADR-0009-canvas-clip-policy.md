# ADR-0009 — Политика геометрии вне canvas: documented clip (REVIEW_M1 M1-N6)

Дата: 2026-07-26. Статус: accepted (M2).

## Контекст

REVIEW_M1 M1-N6: сцена с геометрией целиком за пределами `[0,W]×[0,H]`
валидируется как `Ok(())` — §12 такого инварианта не содержит, но политику
надо было выбрать осознанно ДО появления renderer-а: reject или clip.

## Решение: **documented clip на рендере; валидация не отвергает**

1. **Renderer интегрирует покрытие только по canvas-окну.** Математически:
   coverage(pixel) = ∫∫_pixel w(x,y) dA считается по пикселям canvas;
   геометрия вне окна вкладывается ровно своим пересечением с окном
   (реализация: точное построчное отсечение по y — вклад каждой строки
   независим; колонки правее W сворачиваются в full-cover bucket; рёбра
   левее колонки 0 не видны лучу-вправо ни одного canvas-пикселя).
   Это семантика viewport (как в SVG), а не изменение сцены: canonical
   bytes/digest не затрагиваются.

2. **Валидация вне-canvas геометрию НЕ отвергает.** Причина: legitimate
   producers. Bézier control points законно выходят за canvas, даже когда
   сама кривая остаётся внутри (control-polygon overshoot), а M7-оптимизация
   форм, касающихся края, будет двигать ручки через край. Reject по
   enclosure-боксам дал бы ложные отказы; reject по истинному экстенту
   кривой требует certified-оценок, которые дают ровно ту же информацию,
   что и клиппинг, но ценой ложной строгости.

3. **Партиционные инварианты действуют внутри окна.** Для partition-рендера
   per-pixel проверки диапазона и суммы (ADR-0010) выполняются на canvas;
   вне окна утверждений не делается. Полностью вне-canvas остров даёт
   нулевое покрытие своей face внутри окна — это НЕ нарушение партиции
   (exterior честно покрывает окно единицей), но такая сцена почти
   наверняка бессмысленна для inverse rasterization; решение о её
   отбраковке — уровень evidence/verifier M4+/M7 (лишняя face без
   поддержки в данных проиграет по MDL), не уровень renderer-а.

## Тесты

`vice-render/src/coverage.rs`: полностью вне-canvas прямоугольники со всех
четырёх сторон → нулевой вклад; прямоугольник, пересекающий край, →
суммарное покрытие равно площади пересечения с окном (точность 1e-12);
row-band отсечение битово совпадает с полным рендером тех же строк.
`tests/partition_gate.rs` (C025): partition-инварианты выполняются для
сцены с off-canvas и straddling островами.

## Последствия

- Никакой «геометрия вне canvas = ошибка» семантики не появляется задним
  числом; если будущий milestone захочет reject — это отдельное reviewed
  изменение политики с recalibration последствий.
- Renderer никогда не аллоцирует буферы по экстенту геометрии — только по
  canvas: resource-bound по W×H (ADR-0010), независимо от координат сцены.
